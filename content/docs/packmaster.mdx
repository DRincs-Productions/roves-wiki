[Roves Packmaster](https://github.com/DRincs-Productions/roves-packmaster) is a desktop app that
packages your already-built web game into Roves distributions — without you needing Rust or
Python installed. Point it at your build output, choose what to generate, and it produces
the releases for you.

It never compiles anything: it downloads the engine's own prebuilt <DynamicLink href="/docs/shell">shell</DynamicLink> and
packs your content into it by linking the engine's `roves-content-packer` crate directly as
a library.

<Accordions>

<Accordion title="Prerequisites" id="prerequisites">

**Nothing else, for a portable release.** No Rust, no Python, no `mach` — Packmaster
downloads a prebuilt shell instead of building one.

**For an installer specifically:** Packmaster itself has to be *running* on the matching OS,
and that OS's native packaging tool has to already be installed — WiX on Windows,
`hdiutil` on macOS (built in), `dpkg-deb` on Linux. Packmaster shows a real, live check per
platform rather than assuming; an installer can only ever be built on its own platform,
unlike the portable path.

## 1. Pick your build output

Packmaster points at your bundler's output folder (a Vite.js project's `dist/`, or the
equivalent from any other bundler) — not your source code. It checks for an `index.html`
there, and rejects a folder that still has its own `package.json` (a project's source root,
not its built output — Vite ships an `index.html` at the source root too, so that check
alone can't tell the two apart).

## 2. Configure your release

- **Release info** — game name and version, read from the build folder's parent
  `package.json` when present (the version always follows it fresh; the name is remembered
  per source folder otherwise) and editable either way. These name the generated files and
  the bundled window title.
- **Portable** — a self-contained, double-click-to-run bundle per platform. A real, live
  check (a HEAD request against the targeted shell release's actual asset — see
  <DynamicLink href="/docs/shell">the Shell section</DynamicLink>) shows whether it's
  currently distributable, rather than assuming it always is.
- **Advanced → Compression** — the same tunables as `mach bundle --content-compress`. See
  <DynamicLink href="/docs/integrations/content-packing">Content packing</DynamicLink> for
  how it actually works — that's where this is explained in depth, not here.
- **Advanced → Steam** — a toggle plus your Steam App ID. See
  <DynamicLink href="/docs/integrations/steam">Steam integration</DynamicLink> for the full
  mechanics (the Steam-enabled shell variant, `steam_appid.txt`) — again, explained there,
  not repeated here.
- **Icon** — a single PNG, auto-detected from your build output (`icon.png`, falling back to
  `favicon.ico`) when present, or picked manually via a file dialog. It's applied everywhere
  it's technically possible to apply it: Windows (the running window/taskbar icon, plus the
  packaged `.exe`'s own icon via a generated multi-size `.ico`), Linux (the running
  window/taskbar icon), macOS (the Dock/app icon, via a generated `.icns` written directly
  into the packaged `.app`), and Android (the launcher icon, see below). Leave it unset and a
  game whose bundler already emits its own `icon.png` — for a PWA manifest, say — gets that
  icon for free with no extra step.

<Accordion title="Installers" id="installers">

The **Installable** section produces a real `.msi`/`.dmg`/`.deb` per platform instead of a
portable zip, each with its own live host-OS-and-tool availability check (see the
Prerequisites accordion above) — see <DynamicLink href="/docs/shell">the Shell section</DynamicLink>
for what each installer format actually wraps.

</Accordion>

<Accordion title="Mobile (Android)" id="mobile">

The **Mobile** section builds a real, installable Android `.apk` — no Android Studio, no
Rust/Cargo, nothing to install by hand beyond what Packmaster downloads on first use (a JRE,
the Android SDK command-line tools, and NDK r28c). This is still early/experimental: by
default it produces a debug-signed `.apk`, fine for testing on a device but not for a store
listing or as an update to a previously-installed release. **Windows** is supported alongside
macOS and Linux — this is new and comes with less real-world mileage than the other two
platforms, since it hasn't yet been exercised on a real Windows machine with a real Android
SDK/NDK install; if an Android build fails specifically on Windows, that's the first thing to
suspect, not a surprise. Packmaster shows a real, live availability check per host OS rather
than assuming.

**Release signing:** the same Mobile card's advanced settings can generate a new signing
keystore or import an existing one (path, alias, and both passwords), then build a properly
signed release `.apk` instead of the debug default — needed before an update can be installed
over a previous release, or before publishing anywhere. Keystore credentials are stored in
plain JSON in Packmaster's own config folder, not an OS keychain — the same trust level as
`~/.android/debug.keystore`, not encrypted at rest but never sent anywhere. Like the Windows
support above, this hasn't yet been checked against a real signed install on a device — verify
the resulting `.apk` yourself (`apksigner verify`, or just installing it) before relying on it
for a real release.

Advanced settings live inside this same card (shared with any future mobile platform): app
name, screen orientation, and the icon described above (reused as the Android launcher icon).
Left unset, the app name and orientation are auto-detected from your build output's own
`manifest.webmanifest` (or `manifest.json`/`site.webmanifest`) — a game that already ships a
PWA manifest needs no extra configuration to get a correctly-named, correctly-oriented Android
app.

## 3. Generate

Downloads the shell, packs your content into it, and shows real, per-step progress. Opens
the folder the release was written to when done — a `release/` folder next to wherever
Packmaster itself is running
from, containing one `<your-game-name>_<platform>.zip` per platform.
