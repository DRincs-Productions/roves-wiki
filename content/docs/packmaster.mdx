[Roves Packmaster](https://github.com/DRincs-Productions/roves-ui) is a desktop app that
packages your already-built web game into Roves distributions — without you needing Rust or
Python installed. Point it at your build output, choose what to generate, and it produces
the releases for you.

It never compiles anything: it downloads the engine's own prebuilt shell (see
<DynamicLink href="/docs/shell">the Shell section</DynamicLink>'s "Prebuilt shells" section) and
packs your content into it by linking the engine's `roves-content-packer` crate directly as
a library. Building *Packmaster itself* needs a Rust/Tauri toolchain, same as any Tauri app
— using it doesn't.

<Accordions>

<Accordion title="Prerequisites" id="prerequisites">

**Your game, already built.** Packmaster points at your bundler's output folder (a Vite.js
project's `dist/`, or the equivalent from any other bundler) — not your source code. It
checks for an `index.html` there, and rejects a folder that still has its own
`package.json` (a project's source root, not its built output — Vite ships an `index.html`
at the source root too, so that check alone can't tell the two apart).

**Nothing else, for a portable release.** No Rust, no Python, no `mach` — Packmaster
downloads a prebuilt shell instead of building one.

**For an installer specifically:** Packmaster itself has to be *running* on the matching OS,
and that OS's native packaging tool has to already be installed — WiX on Windows,
`hdiutil` on macOS (built in), `dpkg-deb` on Linux. Packmaster shows a real, live check per
platform rather than assuming; an installer can only ever be built on its own platform,
unlike the portable path.

## Portable distribution

1. **Pick your build output.** See the Prerequisites accordion above for what Packmaster
   expects to find there.
2. **Configure your release:**
   - **Release info** — game name and version, read from the build folder's parent
     `package.json` when present (the version always follows it fresh; the name is
     remembered per source folder otherwise) and editable either way. These name the
     generated files and the bundled window title.
   - **Portable** — a self-contained, double-click-to-run bundle per platform. Each
     platform shows a real, live check (a HEAD request against the targeted shell
     release's actual asset — see <DynamicLink href="/docs/shell">the Shell section</DynamicLink>)
     for whether it's currently distributable, rather than assuming it always is.
   - **Advanced → Compression** — packs your content into compressed archives instead of
     loose files, with the same tunables as `mach bundle --content-compress` (see
     <DynamicLink href="/docs/integrations/content-packing">Content packing</DynamicLink> for
     how that actually works under the hood).
   - **Advanced → Steam** — a toggle plus your Steam App ID. Turning it on downloads the
     Steam-enabled shell variant instead of the plain one (its own live availability check,
     same as Portable above) and writes a `steam_appid.txt` next to the packaged executable
     — Valve's own convention for testing outside the real Steam client. See
     <DynamicLink href="/docs/integrations/steam">Steam integration</DynamicLink> for what your
     game's own code can then do with it.
3. **Generate.** Downloads the shell (cached per version/platform/Steam-variant after the
   first run), packs your content into it, and shows real, per-step progress. Opens the
   folder the release was written to when done — a `release/` folder next to wherever
   Packmaster itself is running from, containing one `<your-game-name>_<platform>.zip` per
   platform.

Every screen is available in nine languages (English, Italian, Chinese, Japanese, Korean,
Spanish, French, Russian, German).

## Distributing installers

The **Installable** section produces a real `.msi`/`.dmg`/`.deb` per platform instead of a
portable zip, each with its own live host-OS-and-tool availability check (see the
Prerequisites accordion above) — see <DynamicLink href="/docs/shell">the Shell section</DynamicLink>
for what each installer format actually wraps.

## Trying it without building it yourself

Packmaster's own CI builds it (portable output) on every push and publishes it to a rolling,
unversioned ["test" release](https://github.com/DRincs-Productions/roves-ui/releases/tag/test)
— its assets are overwritten on every run. Grab a build from there if you don't have (or
don't want to set up) a local Rust/Tauri toolchain.
